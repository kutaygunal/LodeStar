1. Overview & sequencing logic

The four reports agree on one thing: the engineering core is real, but the market-facing surface is missing. The gaps cluster into four layers that must be built in order, because each layer depends on the one before it:

S1
Make it run — a demoable app
S2
Make it execute — real IT&V loop
S3
Make it trustworthy — certification
S4
Make it sellable — multi-user + web
Sequencing logic. You cannot add multi-user collaboration (S4) before there is a runnable app (S1). You cannot prove certification (S3) before the execution loop is real (S2). And you cannot sell (S4) before the headline features run (S1–S2). Each sprint ends with a demonstrable increment.

Each sprint below lists the work items by module, with the priority taken from the source reports. Effort is a relative estimate for a small team. The definition of done for each sprint is a concrete, demoable outcome.

6. Dependency map & definition of done

Dependency map

  • S1 → S2: The desktop app (S1) is the shell that hosts the execution loop (S2). Adapters must be functional (S1) before TestRunner can drive them (S2).
  • S2 → S3: Coverage and evidence (S3) require a real execution path (S2) to produce real results. Semantic evaluation (S2) must precede certification claims (S3).
  • S3 → S4: Multi-user and web (S4) build on a trustworthy core (S3). You cannot sell collaboration on a product whose compliance claims are unproven.
  • Cross-module: TestForge execution (S2) feeds AssureCheck evidence (S3). ScenarioForge baseband (S2) feeds TestForge execution (S2). TraceLink's ReqIF/evidence package is reused by AssureCheck (S3/S4).

Definition of done — whole plan

At the end of the four sprints, Lodestar should be a product where:

  1. A user can run the desktop app and see real data (S1).
  2. A scenario can execute through a real path and produce live measurements (S2).
  3. The platform can prove compliance with real coverage and auditor-ready evidence (S3).
  4. Teams can collaborate in a browser with roles, and the product can be sold with packaging and docs (S4).
Strategic note. The reports agree on positioning: Lodestar should be the orchestration/integration layer wrapping vendor tools (adapters), with novel value in ScenarioForge (software-defined baseband) and RiskAI (LLM-assisted FMEA). The execution gap is that the integration layer and the novel-value modules are exactly the parts that are stubbed. Sprint 1 is essentially "execute the strategy that is already written down."
